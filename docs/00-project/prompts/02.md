# 02 — Database Migrations & Models

## Goal
Build out the full single-restaurant schema from the blueprint and the corresponding Eloquent models.

## Blueprint Reference
§3 (Database Schema), §9 step 2.

## Scope
- All tables from §3: users, roles, permissions, role_permission, categories, menu_items, modifiers/modifier_options, orders, order_items, tax_rates, inventory_items, inventory_transactions, menu_item_inventory, payments.
- **No `tenants` table, no `tenant_id` column on anything, no `impersonation_logs`** — these were multi-tenancy-specific and are deferred per blueprint §10.
- Seeders for the fixed/global `roles` (`admin`, `cashier`, `kitchen_staff`) and `permissions` tables.
- Models with correct relationships. No `BelongsToTenant` trait or equivalent — there's nothing to scope.

## How to work
Use the `plan-council-code-test` skill. Split into multiple small tasks (e.g. one per related table group) rather than one giant migration task.
