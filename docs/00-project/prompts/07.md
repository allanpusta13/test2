# 07 — POS PWA & Offline Resilience

## Goal
Build the offline-first POS Terminal and local receipt printing bridge.

## Blueprint Reference
§7 (Resilience — unchanged in mechanism from earlier versions), §9 step 7.

## Scope
- POS Terminal as a PWA with a service worker and local-first storage (IndexedDB). Since the stack is unified on React, this reuses the same shadcn components and Vite build as the rest of the Admin Panel — it's the offline/service-worker layer that makes it distinct, not a separate framework.
- Offline order queuing reusing the idempotency-key pattern from prompt 06, syncing on reconnect.
- Local menu/price caching, refreshed on reconnect.
- Local print bridge for receipts — networked ESC/POS endpoint, not browser-triggered printing.

## How to work
Use the `plan-council-code-test` skill. The council's testing/ops reviewer should specifically evaluate the offline→online sync plan for double-submission risk before approving.
