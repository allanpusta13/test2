# 07 — Customer Ordering Page

## Goal
Build the public, per-tenant ordering flow: menu, cart, checkout, order tracking.

## Blueprint Reference
§5 (Customer Ordering Page), §11 step 7.

## Scope
- Root route on the tenant subdomain renders the menu directly — no separate landing screen (§5.1).
- Menu browsing with category tabs, cart with modifier selection, session-scoped per tenant.
- Idempotent, rate-limited checkout (§5.3) — client-generated idempotency key, throttle middleware.
- Fulfilment note fixed as "Pay at counter" — no payment-method UI to build.
- Order tracking page using the signed tracking token from prompt 04.

## How to work
Use the `plan-council-code-test` skill. This is the first task with real Pest v4 **browser tests** — plan for `tests/Browser/` coverage of the actual add-to-cart → checkout → tracking flow, not just feature tests of the backend. Use `visit()`, not Dusk syntax.
