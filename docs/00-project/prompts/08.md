# 08 — POS PWA & Offline Resilience

## Goal
Build the offline-first POS Terminal and local receipt printing bridge.

## Blueprint Reference
§9 (Resilience & Physical Operations), §11 step 8.

## Scope
- POS Terminal as a PWA with a service worker and local-first storage (IndexedDB), separate from the server-rendered Filament back-office pages.
- Offline order queuing reusing the idempotency-key pattern from §5.3, syncing on reconnect.
- Local menu/price caching, refreshed on reconnect.
- Local print bridge for receipts (§9.2) — networked ESC/POS endpoint, not browser-triggered printing.

## How to work
Use the `plan-council-code-test` skill. The council's testing/ops reviewer should specifically evaluate the offline→online sync plan for double-submission risk before approving — this is exactly the failure mode the idempotency key exists to prevent, and it's easy to reintroduce it in the sync path if not deliberate.

## Documentation (via Tolaria MCP)
- ADR to `docs/00-project/architecture-decisions/` for the offline sync strategy (what's cached, what's queued, conflict handling on reconnect).
- Research note to `docs/02-research/` on the print bridge implementation, since ESC/POS integration details are hardware-specific and worth having on record for whoever debugs a printer issue later.
