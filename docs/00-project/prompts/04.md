# 04 — Admin Panel: Users & Roles

## Goal
Build the Admin Panel's staff and role management surface — this is what the old "Super Admin Panel" collapsed into now that there's only one restaurant.

## Blueprint Reference
§1 (Admin Panel), §4.1–§4.3 (Application Structure), §9 step 4.

## Scope
- Routes + controllers under `/admin`, gated to the `admin` role only: `UserController`, `RoleController`, each returning `Inertia::render(...)`.
- `Pages/Admin/Users/Index.tsx` — create/edit staff accounts, assign one of the fixed roles (`admin`, `cashier`, `kitchen_staff`).
- `Pages/Admin/Roles/Index.tsx` — **view/assign only**, listing the fixed, seeded roles. No create/delete role UI, and no disabled-button stand-in for one either — that would imply the capability exists.
- `AdminLayout.tsx` — the shared layout for all Admin Panel pages, with role-aware navigation (e.g. `kitchen_staff` shouldn't even see a "Menu" link, not just be blocked from the route).
