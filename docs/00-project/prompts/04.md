# 04 — Broadcast Channel Authorization

## Goal
Set up Reverb channel authorization before any UI depends on real-time order updates.

## Blueprint Reference
§6.3 (Real-Time Channel Authorization), §11 step 4.

## Scope
- `tenant.{tenantId}.orders` private channel, authorized by matching `$user->tenant_id`.
- `order.{orderId}.tracking` channel, authorized via a signed tracking token (customers are anonymous, no login).
- Tests proving Tenant A cannot subscribe to Tenant B's channel (feeds into §10's isolation suite from prompt 02).

## How to work
Use the `plan-council-code-test` skill. This is a security-sensitive task — the council's security/multi-tenancy reviewer should treat any ambiguity in channel scoping as a DENY until resolved, not a minor note.

## Documentation (via Tolaria MCP)
- ADR to `docs/00-project/architecture-decisions/` explaining the signed-token approach for anonymous customer tracking vs. authenticated tenant channels — two different auth models on purpose, worth documenting why.

## Update CLAUDE.md
Add to "Multi-Tenancy Rules": any new broadcast channel must have an explicit authorization callback and a corresponding cross-tenant isolation test before it ships.

## On completion
Full Pest suite passes, including the new channel-isolation tests. Proceed to `docs/00-project/prompts/05.md`.
