# 03 — Broadcast Channel Authorization

## Goal
Set up Reverb channel authorization before any UI depends on real-time order updates.

## Blueprint Reference
§6 (POS Workflow — broadcast channels), §9 step 3.

## Scope
- A single `orders` private channel, authorized to any authenticated user whose role is `admin`, `cashier`, or `kitchen_staff` — **not tenant-scoped**, since there's only one restaurant.
- `order.{orderId}.tracking` channel, authorized via a signed tracking token (customers are anonymous, no login) — unchanged concept from earlier multi-tenant versions.
- `resources/js/lib/echo.ts` — the `laravel-echo` client configuration React components will subscribe through (Kitchen Display, Orders page).
- RBAC tests proving a role without POS/kitchen access cannot subscribe to `orders` (there's no cross-tenant test here — see blueprint §8 for why that suite was removed).

## How to work
Use the `plan-council-code-test` skill. The council's security/access-control reviewer should treat any ambiguity in the channel's role check as a DENY until resolved, same rigor as the old tenant-isolation checks, just applied to roles instead of tenants.

## Documentation
- ADR to `docs/00-project/architecture-decisions/` if the single-channel-with-role-check design was non-obvious or has trade-offs worth recording (e.g. why not per-role channels).
