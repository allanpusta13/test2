# 06 — Tenant Panel Resources

## Goal
Build the Tenant Panel's core resources: Category, MenuItem, Modifier, Order, InventoryItem.

## Blueprint Reference
§4.3 (Tenant Panel), §6 (POS Workflow), §7 (Inventory Management), §8 (Payments), §11 step 6.

## Scope
- Category, MenuItem, Modifier CRUD resources.
- Order resource with the status-transition action baked in: stock deduction fires specifically on the `preparing` transition (§6.4), never elsewhere.
- InventoryItem resource showing derived stock (§7.1) with the locked, concurrency-safe deduction logic (§7.2).
- Cash payment recording (§8), including partial payments — `payment_status` derived from `SUM(payments.amount)` vs `orders.total`, with outstanding balance shown on `partially_paid` orders.

## How to work
Use the `plan-council-code-test` skill. Split into one task per resource. For the Order and InventoryItem tasks specifically, the council's testing/ops reviewer should explicitly check for the concurrency race condition (§7.2) — write a test that fires two simultaneous deduction attempts against the same ingredient before considering this task done.

## Documentation (via Tolaria MCP)
- ADR to `docs/00-project/architecture-decisions/` for the `lockForUpdate` concurrency approach if any alternative (e.g. optimistic locking, queued deductions) was seriously considered and rejected.
- Research note to `docs/02-research/` on any Filament-specific patterns used for the status-transition action or derived-value display.

## Update CLAUDE.md
Add to "Data Model Conventions": stock deduction only happens on `preparing`; cancellations after that point are reversed via a new addition-type transaction, never by mutating the original.
